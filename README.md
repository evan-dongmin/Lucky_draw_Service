# 🎉 타추위 추첨 프로그램

타운홀 미팅용 AI 에이전트 기반 경품 추첨 서비스. 250명 규모 참가자를 대상으로
**5분 안에** 진행되는 공정성 검증 가능한 추첨 + 부서 대항 카트 레이싱 연출 +
참여형 예측 게임(무손실)을 제공합니다.

> 설계 배경과 의사결정 근거는 `타추위-추첨프로그램_기획안.md`, 개발 실행 계획은
> `타추위-추첨프로그램_작업계획서.md`를 참고하세요.

---

## 1. 30초 만에 체험하기 (심사자용 원클릭 데모)

1. [실행](#4-실행-방법)한 뒤 브라우저에서 **무대 화면**(기본 접속 주소)을 엽니다.
2. **"🚀 데모로 체험하기"** 버튼을 누릅니다.
   - 가상 참가자 250명 + 부서가 자동 생성되고,
   - 레이싱+예측 게임 세션이 만들어져 커밋이 즉시 공개되며,
   - 예측 봇 249명이 자동으로 참여해 분포·리더보드를 채우고,
   - 5분 런북이 자동으로 시작됩니다.
3. 별도 브라우저 창에서 `/mobile`을 열어 직접 부서·이름을 선택하고 예측에
   참여해볼 수 있습니다(자기 자신도 봇들 사이에서 함께 경쟁).
4. 5분 후 당첨자가 발표되고, `/verify`에서 공정성 검증을 직접 해볼 수 있습니다.

> ⚠️ 이 저장소에는 스크린샷/GIF를 포함하지 않았습니다. 개발이 브라우저
> 자동화 도구 없는 환경에서 이뤄져 실제 화면 캡처를 생성할 수 없었습니다.
> 대신 위 원클릭 데모로 실제 화면을 30초 안에 직접 확인할 수 있습니다.

## 2. 화면 구성

| 주소 | 대상 | 내용 |
|---|---|---|
| `/` | 대형 스크린(무대) | 부서 통과율 랭킹, 커밋 해시, 레이스 진행, 예측 리더보드, 최종 당첨자 |
| `/admin` | 운영자(사회자) | 명단 등록, 세션 설정, 커밋→추첨→재추첨, 예측 게임 on/off |

| `/verify` | 누구나 | 서버를 신뢰하지 않고 브라우저에서 직접 커밋-리빌 재계산 |

## 3. 핵심 기능

### 공정성 (커밋-리빌)
- 명단·부서 편성·당첨 인원수를 시드와 함께 커밋(SHA-256)해 추첨 **전**에 공개합니다.
- 추첨 후 시드를 공개하면 누구나(`/verify`) 브라우저에서 동일 알고리즘으로
  재계산해 커밋·순위·당첨자가 일치하는지 직접 확인할 수 있습니다.
- `static/fairness.js`는 `app/fairness.py`의 알고리즘을 그대로 이식한 것으로,
  둘이 바이트 단위로 일치함을 Node.js 교차 검증 테스트로 보장합니다
  (`tests/test_js_fairness_parity.py`).

### 3라운드 부서 대항 서바이벌 퍼널
- R1: 전원 출발 → 제한 시간 내 상위 100명 통과 (부서별 통과율 실시간 집계)
- R2: 생존자 중 결선 진출 인원(F) 통과
- R3: 결선 → 도착 순서로 최종 당첨자 N명 확정
- **생존은 항상 개별 참가자 단위로 결정**되고, 부서 순위는 그 결과를 집계한
  표시·예측용 지표일 뿐입니다(부서 통째 탈락 없음 → 당첨자가 중간에 사라지는
  모순이 구조적으로 발생하지 않습니다).
- **무대 화면(전체화면 레이싱 중계)**: 부서 색상 카트가 실시간으로 트랙을
  이동하는 Canvas 렌더링, F1 스타트 라이트(라운드마다 점등→GO 연출),
  라운드별 자동 카메라 전환(R1 광각 → R2 중간 줌 → R3 리더 추적 클로즈업,
  admin에서 수동 전환도 가능), 실시간 포지션 타워, 순위 역전 시 팀
  특수능력 아이콘 이펙트, WebAudio 합성 효과음(외부 음원 파일 없음),
  AI MC 실시간 음성 해설(Web Speech API), 최종 발표 시 시상대+컨페티+
  팡파레, 진행이 밀릴 때 관리자가 현재 레이스만 조기 종료하는 비상 버튼.
  모두 이미 서버가 계산한 결과를 "극적으로 보여주는" 연출일 뿐이며 공정성
  판정 자체에는 관여하지 않습니다.
- **팀 특수능력**: 부서마다 니트로 부스트·배리어 실드 등 8종 중 하나가
  고정 배정됩니다(같은 명단이면 항상 같은 배정). 추월 이펙트·MC 해설
  문구가 팀마다 달라지는 순수 시각 연출이며, 순위·통과 여부에는 어떤
  영향도 주지 않습니다(race.py의 카트별 페이스 지수와 동일한 원리 —
  연출만 다르고 최종 결과는 시드로 완전히 고정).

### 참여형 예측/베팅 게임
세션 생성 시 두 모드 중 하나를 선택합니다(둘 다 완전히 **가산적** —
꺼도 레이싱/룰렛 흐름은 전혀 영향을 받지 않습니다).

- **확신도 배분(기본, 무손실)**: 참가자는 확신도 100을 3라운드에 배분하고,
  라운드별로 부서(R1·R2) 또는 결선 카트(R3)를 예측합니다. **틀려도 0점,
  마이너스 없음.** 라운드 가중치(1.0/1.5/2.5배)가 후반으로 갈수록 커져서
  초반을 다 틀려도 마지막 라운드 적중만으로 역전할 수 있습니다.
- **사이버머니 갬블링(승인 시 선택 가능)**: 사이버머니(시작 500)로 실제
  손실이 있는 베팅을 합니다. 정산은 경마식 **패리뮤추얼 방식** — 맞힌
  사람들이 그 라운드에 걸린 전체 판돈을 자신이 건 비율대로 나눠 가지므로
  운영자가 별도로 지급할 재원이 필요 없고, 잔액은 항상 0 이상입니다.
  실물 경품 당첨자 결정과는 **완전히 분리**되어 있습니다(사이버머니
  잔액은 `draw.winners` 계산에 전혀 관여하지 않는 별도 리더보드).
  라운드 2·3 개방 시 소액 보너스 칩을 지급해 초반 파산이 남은 라운드
  완전 이탈로 이어지지 않게 했습니다. **사내 승인 후에만 사용하세요**
  (Admin 콘솔에 안내 문구가 표시됩니다).
- 두 모드 모두 대상 선택/베팅은 **해당 라운드의 선택 창이 열린 동안에만**
  가능합니다(미리 걸어두고 잊는 것을 방지). 확신도 배분은 시간 내
  미선택 시 커밋된 시드에서 파생된 무작위 값으로 자동 배정되지만(0점
  처리 아님), 갬블링은 **자동 베팅을 하지 않습니다** — 참가자 동의 없이
  가상의 돈이라도 마음대로 거는 것은 다른 문제라 판단했습니다.

### AI MC 에이전트
- 상황별(오프닝/레이스 진행/부서 순위 변동/라운드 통과/최종 발표/검증) 멘트를
  자동 진행 중 자막으로 노출합니다.
- **행사 전 사전 배치 생성만** 하며 레이스 도중 실시간 LLM 호출은 하지
  않습니다. `ANTHROPIC_API_KEY`가 없거나 호출이 실패해도 정적 폴백 멘트로
  완전히 동작합니다.
- 실명·사번·부서명은 절대 외부 API로 전송하지 않습니다(익명 슬롯 템플릿만
  생성 요청 → 실제 값은 로컬에서 치환).

## 4. 실행 방법

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate  /  macOS·Linux: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

브라우저가 자동으로 열립니다(기본 `http://127.0.0.1:8000/`). `ANTHROPIC_API_KEY`
환경변수를 설정하면 MC 멘트를 LLM으로 사전 생성할 수 있으며, 없어도 전 기능이
정상 동작합니다.

같은 Wi-Fi의 다른 기기에서 모바일 화면에 접속하려면 서버 PC의 사설 IP로
접속하세요 (예: `http://192.168.0.10:8000/mobile`). `HOST` 환경변수를
`0.0.0.0`으로 설정하면 외부 접속을 허용합니다.

### 배포(선택)

`Dockerfile`과 `render.yaml`을 포함해두었습니다. Render.com 기준으로는
대시보드에서 "New +" → "Blueprint" → 이 저장소를 선택하면 별도 설정 없이
배포됩니다(웹소켓 지원 확인됨). 무료 플랜은 트래픽이 없으면 슬립되므로,
행사 당일에는 시작 10~15분 전에 한 번 접속해 깨워두는 것을 권장합니다.
행사 PC에서 로컬로 실행하는 것도 여전히 가장 안전한 방식이며(네트워크
불확실성이 없음), 배포 주소는 원격 심사자가 사전에 미리 체험해볼 수
있게 하는 보조 수단으로 추천합니다.

### 운영자 진행 순서 (실제 행사용)

1. `/admin`에서 명단을 붙여넣기/업로드하고(또는 샘플 생성), 당첨 인원수·
   모드(룰렛 또는 레이싱)·총 진행 시간(기본 300초)을 설정. 예측 게임을
   켜면 확신도 배분(기본)/사이버머니 갬블링(승인 시) 중 선택 → **세션 생성**
2. **① 커밋 생성** — 무대 화면에 커밋 해시가 공개됩니다. 레이싱 모드라면
   이 시점부터 모바일 R1 선택 창이 열립니다(온보딩 겸용).
3. 룰렛 모드: **② 추첨 시작(리빌)** 한 번으로 종료.
   레이싱 모드: **② 레이스 시작**을 누르면 5분 런북이 자동 진행됩니다.
4. 필요 시 **재추첨**(이전 당첨자 제외 옵션) 또는 **전체 초기화**.

## 5. 테스트

```bash
pytest -q
```

290여 개 테스트가 공정성 엔진의 결정론·위변조 탐지, 부서 통과율 계산,
레이스 판정과 Fairness 결과 100% 일치(다수 시드 반복 검증), 예측/갬블링
게임 채점·정산·선택창 상태머신, 서버 재시작 후 상태 복원, 두 게임 모두
off 상태에서의 회귀 없음 등을 검증합니다. Node.js가 설치되어 있으면 JS
공정성 이식본과의 교차 검증도 함께 실행됩니다.

### 부하 테스트(시뮬레이션)

실제 250대 물리 기기·행사장 Wi-Fi 환경은 이 개발 환경에서 재현할 수 없어,
asyncio 기반 스크립트로 그 부하 패턴을 시뮬레이션합니다:

```bash
python run.py &          # 서버 실행
python scripts/load_test.py --count 250
```

WebSocket 250개 동시 접속 + 250명 동시 참여(join)·확신도 배분·1라운드 선택
요청에 대한 성공률과 지연시간(p50/p95/max)을 출력합니다. **행사 전에는 반드시
실제 기기·행사장 네트워크로도 실측하는 것을 권장합니다.**
